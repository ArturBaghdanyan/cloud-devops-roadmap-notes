# ☁️ Amazon Simple Storage Service (Amazon S3) — Comprehensive Guide

---

## 1. Ի՞նչ է Amazon S3-ը (Overview)

**Amazon S3 (Simple Storage Service)**-ը AWS-ի ամենաառաջին (գործարկվել է 2006թ․) և ամենահիմնարար ծառայություններից մեկն է։ Այն հանդիսանում է **Object Storage** (օբյեկտային պահոց), որը նախատեսված է ցանկացած ծավալի անստրուկտուրացված տվյալներ (նկարներ, վիդեոներ, backup-ներ, log-եր, static web էջեր) պահպանելու համար։

### 🌟 4 Հիմնական Սյուները (Key Properties from Lesson)

1. **Object Storage:** Տվյալները պահվում են որպես ամբողջական օբյեկտներ HTTP API-ի միջոցով։ Սա OS-ին կցվող դիսկ (HDD/SSD) կամ ֆայլային համակարգ չէ։

2. **Region-Resilience (տարածաշրջանային կայունություն):** Թեև Bucket-ը ստեղծվում է մեկ կոնկրետ Region-ում, **S3 Standard**-ը ձեր տվյալները ավտոմատ կերպով կրկնօրինակում է (replicate) առնվազն **3 Availability Zone (AZ)**-ներում։

3. **Public-Zone Service:** S3-ը հասանելի է ինտերնետից Public Endpoints-ի միջոցով (REST API / HTTPS)։ **ԿԱՐԵՎՈՐ:** Լռելյայն (default) բոլոր ստեղծված Bucket-ներն ու Object-ները **ՄԱՍՆԱՎՈՐ ԵՆ (Private)**։

4. **Practically Unlimited:** Չկա տարողության սահմանափակում։ Վճարում եք միայն իրական օգտագործված Gigabyte-ների, կատարված հարցումների (PUT/GET) և Data Out-ի համար։

## 2. S3 vs Այլ պահոցներ (Block vs File vs Object Storage)

Հարցազրույցներում սա ամենահաճախ տրվող հարցերից է․

| Հատկանիշ                  | Object Storage (Amazon S3)        | Block Storage (AWS EBS)              | File Storage (AWS EFS)        |
| :------------------------ | :-------------------------------- | :----------------------------------- | :---------------------------- |
| **Տվյալների տեսակը**      | Ամբողջական ֆայլ + Metadata        | Byte blocks (հում սեկտորներ)         | Ֆայլեր ու թղթապանակներ (NFS)  |
| **Մուտքի մեթոդը**         | HTTP/HTTPS API (GET, PUT)         | OS Drive (Mounted disk: `/dev/sda1`) | Shared Network Drive          |
| **Արագություն (Latency)** | Միլիվայրկյաններ (10-100ms)        | Ultra-fast (Միկրովայրկյաններ)        | Low latency (ms)              |
| **Մասշտաբայնություն**     | Անսահմանափակ (Petabytes+)         | Սահմանափակվում է դիսկի չափով         | Ավտոմատ մեծացող               |
| **Կիրառություն**          | Backups, Media assets, Static Web | Օպերացիոն համակարգեր, DB             | Shared media, CMS (WordPress) |

## 3. Հիմնական հասկացությունները (Core Concepts)

### 📦 1. Bucket (Զամբյուղ)

Bucket-ը S3-ում օբյեկտների բարձրագույն մակարդակի կոնտեյներն է։

- **Region Binding:** Bucket-ը ստեղծվում է կոնկրետ AWS Region-ում (օր․՝ `eu-central-1`):
- **Immutability:** **Անունը և Region-ը հնարավոր չէ փոխել** ստեղծելուց հետո։
- **Global Uniqueness Rule:** Bucket-ի անունը պետք է լինի **ԳԼՈԲԱԼ ՅՈՒՐԱՀԱՏՈՒԿ (Globally Unique)** ամբողջ AWS աշխարհում։ Եթե ինչ-որ մեկն արդեն վերցրել է `my-bucket` անունը, դուք չեք կարող այն օգտագործել։
- **Bucket Naming Rules:**
  - 3-ից 63 նիշ երկարություն։
  - Միայն փոքրատառեր (`a-z`), թվեր (`0-9`) և հիֆեն (`-`):
  - Չի կարող սկսվել կամ ավարտվել հիֆենով։
  - Չի կարող պարունակել IP հասցեների ձևաչափ (օր.՝ `192.168.1.1`):

### 📄 2. Object (Օբյեկտ)

S3-ում պահվող յուրաքանչյուր ֆայլ կոչվում է **Object**:

- **Չափսեր:** 0 byte-ից մինչև **5 Terabytes (TB)** մեկ ֆայլի համար։
- **Բաղադրիչները:**
  - **Data (Payload):** Ֆայլի բովանդակությունը (նկար, pdf, zip):
  - **Metadata:** Key-value զույգեր ֆայլի մասին (օր․՝ `Content-Type: image/jpeg`, `size: 2.4MB`, `last-modified`):
  - **Version ID:** Եթե Versioning-ը միացված է։

### 🔑 3. Key (Բանալի)

Key-ը օբյեկտի **ամբողջական անվանումն (Full Path)** է Bucket-ի ներսում։

- S3-ը **Key-Value Store** է։
- **Օրինակ:**
  - Bucket: `my-company-data`
  - Key: `docs/2026/report.pdf`
  - Value: `[PDF File Bytes]`

### 📂 4. Folders aren't real! ("Սուտ" թղթապանակներ)

**ԿԱՐԵՎՈՐ ԿՈՆՑԵՊՏ:** S3-ում գոյություն չունեն իրական թղթապանակներ (Directories)։ S3-ը **Flat (հարթ)** պահոց է։

- Երբ տեսնում եք `docs/2026/report.pdf`, AWS Console-ը ձեզ ցույց է տալիս `docs/2026/` որպես թղթապանակ միայն **օգտատիրոջ հարմարավետության համար**:
- Իրականում `docs/2026/` տեքստը ուղղակի **Key Prefix** է (սկզբնամաս):

### High Availability & Durability (Հուսալիություն)

- **Durability (Տվյալների պահպանվածություն):** **99.999999999% (11 nines)**. Սա նշանակում է, որ եթե S3-ում պահեք 10,000,000 օբյեկտ, հավանական է, որ 10,000 տարում կկորցնեք ընդամենը 1 ֆայլ։
- **How it achieves this:** Ֆայլը վերբեռնելիս S3-ը այն ակնթարթորեն գրում է նույն Region-ի **առնվազն 3 տարբեր AZ-ների** ֆիզիկական սերվերներում։

## 5. S3 Storage Classes (Պահպանման դասեր)

S3-ը առաջարկում է տարբեր Storage Class-ներ՝ ծախսերը օպտիմալացնելու համար (ըստ տվյալների օգտագործման հաճախականության)․

1. **S3 Standard:** Հաճախակի օգտագործվող տվյալների համար (High availability, 3+ AZs):
2. **S3 Standard-IA (Infrequent Access):** Հազվադեպ կարդացվող, բայց արագ հասանելիություն պահանջող տվյալների համար (ավելի էժան է պահելը, բայց կարդալը վճարովի է):
3. **S3 One Zone-IA:** Պահվում է միայն 1 AZ-ում (30% էժան է IA-ից, բայց AZ-ի խափանման դեպքում տվյալները կկորչեն):
4. **S3 Glacier Flexible Retrieval / Deep Archive:** Արխիվային տվյալների համար (ամենաէժանը)։ Ֆայլը ստանալու համար պահանջվում է րոպեներից մինչև ժամեր։

## 6. S3-ի Անվտանգությունը (Security & Access Management)

1. **Block Public Access:** Defualt կարգավորում, որը արգելափակում է ցանկացած հանրային մուտք դեպի Bucket:
2. **Bucket Policies:** JSON ձևաչափով գրվող կանոններ, որոնք կցվում են Bucket-ին (օրինակ՝ թույլատրել որոշակի IP-ների մուտքը):
3. **IAM Policies:** Օգտատերերին (IAM Users/Roles) տրվող թույլտվություններ։
4. **Encryption (Վերծանման կանխարգելում):**
   - **SSE-S3:** Server-side encryption AWS-ի բանալիներով (Default):
   - **SSE-KMS:** Encryption՝ AWS KMS բանալիների կառավարմամբ։

## 8. ❓ Հաճախ տրվող հարցազրույցի հարցեր և պատասխաններ (Interview Q&A)

### Q1: Կարո՞ղ եմ փոխել S3 Bucket-ի անունը կամ Region-ը ստեղծելուց հետո։

**Պատասխան:** Ո՛չ: Bucket-ի անունը և Region-ը անփոփոխ են (Immutable): Եթե ցանկանում եք փոխել, պետք է ստեղծեք նոր Bucket նոր անունով/Region-ում և տվյալները տեղափոխեք այնտեղ։

### Q2: Ի՞նչ կլինի, եթե AWS Region-ի մեկ Availability Zone-ը (AZ) ամբողջությամբ փլուզվի կամ հոսանքազրկվի։

**Պատասխան:** S3 Standard-ում ձեր տվյալները ապահով կմնան, քանի որ S3-ը ավտոմատ կերպով ֆայլի պատճենները պահում է առնվազն **3 տարբեր AZ-ներում**։ Հավելվածը կշարունակի աշխատել մյուս AZ-ներից։
