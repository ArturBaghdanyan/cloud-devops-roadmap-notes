# 🌐 AWS Custom VPC — Ամբողջական և Համառոտ Ուղեցույց

---

## 1. ⚙️ Ինչ է AWS-ը ստեղծում ավտոմատ (When Creating a Custom VPC)

Երբ դուք ստեղծում եք **Custom VPC**, AWS-ը ավտոմատ կերպով ձեզ համար ստեղծում է հետևյալ 6 բաղադրիչները.

1. **Main Route Table:** Սկզբնական երթուղղման աղյուսակ (`10.20.0.0/16 -> local`): Բոլոր Subnet-ները default օգտագործում են սա, քանի դեռ ուրիշը չեք կցել։
   - Անալոգիա: Սա շենքի հիմնավորված «Որտեղից ուր գնալ» քարտեզն է մուտքի մոտ։
   - Ինչ է անում: Քանի դեռ ուրիշ քարտեզ (Route Table) չեք կցել ենթացանցին, բոլորը նայում են այս գլխավորին:
     Այն ասում է. «Եթե ուզում ես շենքի ներսում (Local) խոսել մեկ այլ սենյակի հետ, ահա ներքին ճանապարհը»:

2. **Default Network ACL (NACL):** Stateless ցանցային firewall: default **թույլատրում է** ամբողջ incoming
   (ներս եկող) և outgoing (դուրս գնացող) traffic-ը:
   - Անալոգիա: Սա շենքի ընդհանուր պարիսպն ու մուտքի անցակետն է։
   - Ինչ է անում: Այն Stateless է (չի հիշում հարցումների պատմությունը): AWS-ի կանխադրված (default)
     ACL-ը շատ «բարի» է՝ թույլ է տալիս բոլոր մուտքային և ելքային տրաֆիկը (Allow All): Եթե ուզեք խստացնել անվտանգությունը, այստեղ կարող եք արգելել կոնկրետ IP-ներ:

3. **Default Security Group:** Stateful firewall: Թույլատրում է ներսի traffic-ը նույն Security Group-ի
   անդամներից և բոլոր outgoing հարցումները:
   - Անալոգիա: Սա ձեր կոնկրետ աշխատասենյակի խելացի կողպեքն ու դուռն է:
   - Ինչ է անում: Այն Stateful է (հիշում է context-ը): Եթե դուք ներսից դուրս եք նայում կամ հարցում անում,
     այն ավտոմատ հիշում է ու հետ եկող պատասխանը ներս է թողնում առանց լրացուցիչ կանոնների: Default SG-ն
     թույլ է տալիս, որ նույն խմբի սարքերը ազատ խոսեն իրար հետ:

4. **DHCP Options Set:** Սերվերներին ասում է, թե որ DNS սերվերն օգտագործեն (`AmazonProvidedDNS`):
   - Անալոգիա: Երբ նոր աշխատակից (սարք) է մտնում շենք, այս բյուրոն նրան բացատրում է կանոնները։
   - Ինչ է անում: Այն ավտոմատ կերպով սերվերներին (EC2) տրամադրում է կարևոր տեղեկություններ՝
     օրինակ, թե որ DNS սերվերն օգտագործեն (AmazonProvidedDNS), որպեսզի կարողանան անուններ թարգմանել IP-ների:

5. **VPC Router:** Անտեսանելի, բարձր հասանելիությամբ (Highly Available) Layer 3 երթուղղիչ, որը գտնվում է
   յուրաքանչյուր Subnet-ի `.1` հասցեում (օրինակ՝ `10.20.0.1`):
   - Անալոգիա: Սա շենքի կենտրոնական միջանցքն ու հարկերի միջև անցումն է, որով շարժվում են մարդիկ։
   - Ինչ է անում: Տեխնիկական մակարդակում այն անտեսանելի Layer 3 երթուղղիչ է, որը գտնվում է յուրաքանչյուր
     Subnet-ի ամենաառաջին հասցեում՝ .1-ում (օրինակ՝ 10.20.0.1): Երբ մի սենյակից տվյալը գնում է մյուսը,
     այն անցնում է այս երթուղղիչով։

6. **Amazon DNS Server:** Գտնվում է `VPC_Base + 2` հասցեում (օրինակ՝ `10.20.0.2`) և `169.254.169.253` IP-ում:
   - Անալոգիա: Հեռախոսային գրքույկ, որտեղ անունը հավաքելիս միանգամից միանում եք ճիշտ սենյակին։

   - Ինչ է անում: Այն թարգմանում է դոմենային անունները (օրինակ՝ google.com) IP հասցեների։ Այն միշտ ապրում է
     ձեր VPC-ի հիմնական հասցեից երկրորդ տեղում՝ VPC_Base + 2 (օրինակ՝ 10.20.0.2), ինչպես նաև AWS-ում բոլոր
     սերվերների համար հասանելի է ստանդարտ 169.254.169.253 կախարդական հասցեով։

> ⚠️ **ԿԱՐԵՎՈՐ (Not Created):** Custom VPC ստեղծելիս AWS-ը **ՉԻ ՍՏԵՂԾՈՒՄ** Subnet-ներ, Internet Gateway (IGW) և NAT Gateway: Նոր Custom VPC-ն դատարկ է և փակ է ինտերնետից:

## 2. 🚦 VPC Router-ը և Route Table-ի Կանոնները

VPC Router-ը աշխատում է Layer 3-ում(Network) և երթուղղում է փաթեթները ըստ Destination IP-ի:

### 🎯 Ամենակարևոր Կանոնը՝ "Longest Prefix Match"

> **Higher Prefix = More Specific = Higher Priority**

Եթե երթուղղման աղյուսակում (Route Table) կա երկու համընկնող կանոն.

- `10.20.0.0/16 -> local`
- `0.0.0.0/0 -> igw-xxx`

Եթե փաթեթն ուղարկվում է `10.20.16.25` IP-ին, ապա այն համապատասխանում է և՛ `/16`-ին, և՛ `/0`-ին: **`/16`-ը ավելի սպեցիֆիկ է (հաղթում է)**, ուստի traffic-ը մնում է VPC-ի ներսում (local):

## 3. 🌐 Internet Gateway (IGW) — VPC-ի Դուռը դեպի Ինտերնետ

Internet Gateway-ը VPC-ն միացնում է AWS Public Zone-ին (ինտերնետին):

### 🛠️ Public Subnet Ստեղծելու 6 Քայլերը.

1. Ստեղծել **Internet Gateway**:
2. Կապել այն VPC-ին (**Attach to VPC**):
3. Ստեղծել custom Route Table (օրինակ՝ `catsdogs-public`):
4. Կցել (Associate) այն **Public Subnet**-ին:
5. Ավելացնել Default Route՝ `0.0.0.0/0 -> IGW` (և IPv6-ի համար `::/0 -> IGW`):
6. Subnet-ի վրա ակտիվացնել **Auto-assign Public IPv4** option-ը:

## 4. 🔄 Ինչպես է IGW-ն աշխատում Public IPv4-ի հետ (1:1 Static NAT)

EC2 instance-ը **երբեք չի տեսնում իր Public IP-ն**: Օպերացիոն համակարգում (`ip addr`) երևում է միայն Private IP-ն (օրինակ՝ `10.20.0.25`):

- **Outbound (Դուրս գնացող):** EC2 (`10.20.0.25`) $\rightarrow$ IGW փոխում է Source IP-ն դարձնելով Public IP (`3.120.45.67`) $\rightarrow$ Ինտերնետ (`203.0.113.50`):
- **Reply (Պատասխան):** Ինտերնետ $\rightarrow$ IGW փոխում է Destination IP-ն դարձնելով Private IP (`10.20.0.25`) $\rightarrow$ EC2:

> 💡 IGW-ն կատարում է **1:1 Static NAT** (Network Address Translation):

## 6. 🧠 DNS-ը VPC-ի Ներսում (Amazon DNS Server / Route 53 Resolver)

3. **Public Internet Domains:** `aws.amazon.com` $\rightarrow$ Public IP

## 7. ⚙️ VPC DNS Settings & Instance Hostnames

### ⚙️ Երկու Կարևոր DNS Պարամետր VPC-ում.

1. **DNS Resolution (`enableDnsSupport`):** Ակտիվացնում է Amazon DNS սերվերը (Default: `ON`):
2. **DNS Hostnames (`enableDnsHostnames`):** Public IP ունեցող instance-ներին տալիս է Public DNS name (Default Custom VPC-ում: `OFF`):

> 📌 **Rule of Thumb:** Միշտ **միացրեք (Turn ON)** երկու պարամետրերն էլ Custom VPC ստեղծելիս, քանի որ Private Hosted Zones-ը և VPC Endpoint-ները պահանջում են երկուսն էլ:

### 🏷️ Hostname-երի Ֆորմատները.

- **Private Hostname (Default IP name):** `ip-10-20-16-25.eu-central-1.compute.internal` $\rightarrow$ `10.20.16.25`
- **Private Hostname (Resource name):** `i-0a1b2c3d4e5f67890.eu-central-1.compute.internal` $\rightarrow$ `10.20.16.25`
- **Public Hostname:** `ec2-3-120-45-67.eu-central-1.compute.amazonaws.com` $\rightarrow$ `3.120.45.67`

## 📐 1. Private vs. Public IP Range-եր (RFC 1918)

Ցանցերում IP հասցեները տարբերակվում են ըստ իրենց առաջին 2 օկտետների (թվերի)․

| Տիրույթ                         | Տեսակ           | Նկարագրություն                                                                   |
| :------------------------------ | :-------------- | :------------------------------------------------------------------------------- |
| `10.0.0.0 – 10.255.255.255`     | 🔒 **Private**  | Լիովին private տիրույթ (հաճախ օգտագործվում է AWS VPC-ում)                        |
| `172.16.0.0 – 172.31.255.255`   | 🔒 **Private**  | Միայն 16-ից 31-ն են private (օր. `172.19.x.x` = Private, `172.192.x.x` = Public) |
| `192.168.0.0 – 192.168.255.255` | 🔒 **Private**  | Միայն 168-ն է private (օր. տնային ռոութերներ)                                    |
| `127.0.0.0/8`                   | 💻 **Loopback** | Localhost (սարքի ներքին հասցեն, որը դուրս չի գալիս ցանց)                         |
| _Ցանկացած այլ IP_               | 🌍 **Public**   | Ինտերնետում հասանելի հանրային IP հասցեներ                                        |

## 🎯 2. AWS VPC-ի 5 Հիմնական Հասկացությունները (Interview Cheat-Sheet)

### 1. VPC (Virtual Private Cloud) – Մեկուսացված Տարածք

Ամպային միջավայրում ձեր անձնական, լիովին վերահսկվող վիրտուալ ցանցն է, որտեղ անվտանգ տեղակայվում են ձեր բոլոր սերվերներն ու բազաները։

### 2. CIDR Blocks & IP Sizing – Հասցեների Պլանավորում

Սկզբնական IP տիրույթն է (օրինակ՝ `10.0.0.0/16`), որը որոշում է ցանցի հասանելի IP-ների քանակը (65k+)։ Պլանավորման ժամանակ պետք է խուսափել overlapping (հատվող) CIDR-ներից՝ ապագա VPC Peering-ների կամ VPN-ների համար։

### 3. Public vs. Private Subnets – Անվտանգության Բաժանում

- **Public Subnet:** Ունի ուղիղ կապ ինտերնետի հետ (Internet Gateway-ի միջոցով)․ նախատեսված է Load Balancer-ների (ALB) և վեբ սերվերների համար։
- **Private Subnet:** Փակ է ինտերնետից․ այստեղ անվտանգ պահվում են տվյալների բազաները (RDS) և բեքենդ միկրոսերվերները։

### 4. Route Tables – Երթուղիների Քարտեզ

Կանոնների աղյուսակ, որը հստակ որոշում է, թե ցանցային տրաֆիկը որտեղ պետք է ուղղվի (օրինակ՝ ներքին տրաֆիկը՝ `local`, դեպի ինտերնետը՝ `IGW` կամ `NAT Gateway`)։

### 5. Security Layers – Երկշերտ Պաշտպանություն

- **Security Groups (SG):** Աշխատում են կոնկրետ ինստանսի (սերվերի) մակարդակում (stateful)։
- **Network ACLs (NACL):** Աշխատում են ամբողջ Subnet-ի մակարդակում (stateless)։
